# SWAYAM ADMISSION — PHASE 6 EMAIL PROVIDER SETUP GUIDE
## Transactional Relay Configuration, Sender Identity & Deliverability Setup

**Target Audience:** DevOps Engineers, Cloud Infrastructure Administrators, System Administrators  
**Applicable Services:** Backend (Render), DNS Provider, Amazon Web Services (SES), Twilio SendGrid  
**Date:** October 21, 2026

---

## 1. Overview & Provider Evaluation

Swayam Admission requires a dedicated transactional email relay to replace the free-tier personal Gmail SMTP sender (`swayamadmissions@gmail.com`), which is currently subject to Google's strict rolling daily sending limit (`550-5.4.5`).

The backend architecture uses a unified, provider-agnostic `EmailChannel` based on Nodemailer and PostgreSQL durable outbox queueing. The application natively supports standard SMTP relays with zero code changes, requiring only environment variable configuration.

### Recommended Providers
1. **Amazon Simple Email Service (SES) — Recommended:**
   - **Cost:** Highly economical ($0.10 per 1,000 emails).
   - **Performance:** Excellent inbox placement, strict deliverability compliance, regional endpoints (e.g. `ap-south-1` Mumbai for low latency in India).
   - **Integration:** Standard SMTP on port 587 (STARTTLS). Webhook tracking via Amazon SNS HTTP/HTTPS subscription.
2. **Twilio SendGrid:**
   - **Cost:** Free tier (100 emails/day), transitioning to paid Essentials tier.
   - **Integration:** Standard SMTP on `smtp.sendgrid.net:587` with username `apikey` and API key as password. Event Webhook posts JSON arrays directly to the backend.

## 2. Option A: Amazon SES Setup Procedure (Recommended)

### Step 1: AWS Account & Identity Setup
1. Log in to the [AWS Management Console](https://console.aws.amazon.com/ses/) and select the **Asia Pacific (Mumbai) `ap-south-1`** region (or your preferred region).
2. Navigate to **SES > Configuration > Verified identities**.
3. Click **Create identity**:
   - **Identity type:** Select **Domain** (e.g. `swayamadmission.com` once purchased) OR **Email address** (e.g. `admin@swayamadmission.com` / current authorized email for staging).
   - If setting up for staging before domain registration, verify your authorized administrative email address by clicking the verification link AWS sends.
4. If in the SES Sandbox:
   - AWS SES accounts start in the "SES Sandbox" where you can only send to verified email addresses.
   - To send to any recipient, submit a request via **SES > Account dashboard > Request production access**. Describe transactional use cases (OTP verification, student admission status, employee account recovery).

### Step 2: Generate SES SMTP Credentials
1. In the AWS SES Console, navigate to **Account dashboard > SMTP settings**.
2. Note your **SMTP endpoint** (e.g., `email-smtp.ap-south-1.amazonaws.com`).
3. Click **Create SMTP credentials**.
4. AWS will generate an IAM user with appropriate SES sending permissions (`ses:SendRawEmail`).
5. Download or safely copy:
   - **IAM Username:** (e.g., `ses-smtp-user.20261021`)
   - **SMTP Username:** (e.g., `AKIAIOSFODNN7EXAMPLE`)
   - **SMTP Password:** (e.g., `BGw3ExamplePassword12345...`)
   > [!IMPORTANT]
   > SES SMTP passwords are NOT standard AWS Secret Access Keys; they are cryptographically derived SMTP credentials generated by the SES console.

### Step 3: Configure Render Environment Variables
In your Render Dashboard for the backend service (`swayam-admission`), navigate to **Environment** and set:

```env
EMAIL_PROVIDER=AMAZON_SES
AWS_REGION=ap-south-1
SMTP_HOST=email-smtp.ap-south-1.amazonaws.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=AKIAIOSFODNN7EXAMPLE
SMTP_PASSWORD=BGw3ExamplePassword12345...
SMTP_FROM_EMAIL=admin@swayamadmission.com
SMTP_FROM_NAME=Swayam Admission
```

*(Note: During staging before domain purchase, `SMTP_FROM_EMAIL` must match the verified email in SES).*

### Step 4: Configure SNS Webhook for Delivery Events (Optional but Recommended)
1. In AWS SNS, create a standard Topic named `ses-delivery-events`.
2. In AWS SES > **Configuration sets** > create a configuration set named `swayam-production`.
3. Add Event destinations for **Delivery**, **Bounce**, and **Complaint**, targeting the `ses-delivery-events` SNS topic.
4. In SNS, create an HTTPS Subscription pointing to:
   `https://swayam-admission.onrender.com/v1/notifications/webhook/ses`
5. The backend automatically responds to the AWS `SubscriptionConfirmation` challenge and validates the subscription.

## 3. Option B: Twilio SendGrid Setup Procedure

### Step 1: Account & API Key Generation
1. Log in to [SendGrid](https://app.sendgrid.com/).
2. Navigate to **Settings > API Keys** and click **Create API Key**.
3. Choose **Restricted Access** and grant full access to **Mail Send**.
4. Copy the generated key (starts with `SG.`).

### Step 2: Sender Identity Verification
1. Navigate to **Settings > Sender Authentication**.
2. Complete **Single Sender Verification** (for staging email) or **Domain Authentication** (for `swayamadmission.com`).

### Step 3: Configure Render Environment Variables
In your Render Dashboard for the backend service, set:

```env
EMAIL_PROVIDER=SENDGRID
SMTP_HOST=smtp.sendgrid.net
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=apikey
SMTP_PASSWORD=SG.your_sendgrid_api_key_here
SMTP_FROM_EMAIL=swayamadmissions@gmail.com
SMTP_FROM_NAME=Swayam Admission
```

### Step 4: Configure Event Webhook
1. In SendGrid, navigate to **Settings > Mail Settings > Event Webhook**.
2. Set **HTTP Post URL** to:
   `https://swayam-admission.onrender.com/v1/notifications/webhook/sendgrid`
3. Check the following events:
   - **Delivered**
   - **Bounced**
   - **Dropped**
   - **Spam Report**
4. Enable Event Webhook and click **Save**.

## 4. Port and TLS Protocol Configuration Rules

The application strictly validates SMTP ports and TLS handshakes:

| Port | `SMTP_SECURE` | Protocol | Notes |
|---|---|---|---|
| **`587`** | `false` | **STARTTLS** | Recommended for Amazon SES, SendGrid, and Google SMTP. Starts plaintext on port 587 and immediately upgrades to TLS 1.2/1.3 via the STARTTLS command. |
| **`465`** | `true` | **Direct SSL/TLS** | Direct encrypted connection established on socket open. Must set `SMTP_SECURE=true`. |
| **`25`** | `false` | Plain / STARTTLS | Often blocked by cloud hosts (AWS/Render/GCP) to prevent spam. Avoid using port 25. |

## 5. Domain DNS Deliverability Roadmap (`swayamadmission.com`)

Once the official domain is registered with a DNS registrar (e.g. Cloudflare, Namecheap, GoDaddy), publish the following records before sending from `@swayamadmission.com`.

### 5.1 SPF (Sender Policy Framework)
SPF designates which mail servers are authorized to send email on behalf of your domain.

- **For Amazon SES:**
  ```text
  Type: TXT
  Host / Name: @
  Value: v=spf1 include:amazonses.com ~all
  TTL: 3600
  ```
- **For SendGrid:**
  ```text
  Type: TXT
  Host / Name: @
  Value: v=spf1 include:sendgrid.net ~all
  TTL: 3600
  ```

> [!CAUTION]
> Never publish multiple SPF TXT records on a single domain. If an SPF record already exists, combine the mechanisms (e.g., `v=spf1 include:amazonses.com include:_spf.google.com ~all`).

### 5.2 DKIM (DomainKeys Identified Mail)
DKIM provides a cryptographic signature verifying that emails were not tampered with in transit.

- **Amazon SES Easy DKIM:**
  AWS SES generates three CNAME records in the console (e.g. `token1._domainkey.swayamadmission.com`, `token2._domainkey`, `token3._domainkey`). Add all three CNAME records to your DNS.
- **SendGrid Automated Security:**
  SendGrid generates two CNAME records (e.g. `s1._domainkey.swayamadmission.com` pointing to `s1.domainkey.uXXXX.sendgrid.net`). Add both CNAME records to your DNS.

### 5.3 DMARC (Domain-based Message Authentication, Reporting & Conformance)
DMARC instructs receiving mail servers (such as Gmail and Yahoo) on how to handle emails that fail SPF or DKIM checks. In 2024, Google and Yahoo made DMARC mandatory for bulk senders.

Add the following initial monitoring record:
```text
Type: TXT
Host / Name: _dmarc.swayamadmission.com
Value: v=DMARC1; p=none; sp=none; rua=mailto:dmarc-reports@swayamadmission.com; pct=100
TTL: 3600
```
- Start with `p=none` (monitoring mode) to verify that all legitimate transactional emails pass SPF and DKIM.
- After 2–4 weeks of clean deliverability, transition to `p=quarantine` and eventually `p=reject`.

## 6. Live Verification & Testing Procedure

After saving the environment variables on Render:

1. **Verify Backend Deployment:** Ensure Render completes deployment successfully (`npm run start:prod`).
2. **Execute Diagnostic Connection Probe:**
   Trigger the diagnostic connection endpoint from the Admin portal or via API call:
   ```bash
   curl -X POST https://swayam-admission.onrender.com/v1/notifications/campaigns/test-email-connection \
     -H "Authorization: Bearer <ADMIN_JWT_TOKEN>"
   ```
   **Expected Response:**
   ```json
   {
     "success": true,
     "provider": "AMAZON_SES",
     "host": "email-smtp.ap-south-1.amazonaws.com",
     "port": 587,
     "status": "READY",
     "user": "AKI***PLE",
     "message": "Live SMTP handshake successfully verified with AMAZON_SES."
   }
   ```
3. **Execute Controlled Single Send:**
   Trigger a password recovery or test notification to an authorized tester email address.
4. **Confirm Inbox Placement:**
   Check the recipient inbox, verify the sender shows `Swayam Admission <admin@swayamadmission.com>`, and inspect email headers to confirm `spf=pass` and `dkim=pass`.
